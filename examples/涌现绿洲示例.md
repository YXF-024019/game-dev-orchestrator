### 3.3g 本轮锁定范围
1. 扩散：以有水格为中心向外 5 格（多源 BFS，流动水也算）
2. 预算：min(3.0, 泉眼储备) 均分到扩散格，格数越多每格越少

1. 不向高处流（水方块只补给 ≤ 泉眼层级的格子）
2. 泉眼储量上限 100（不改）
3. 性能基线（扫描 < 350ms、FPS ≥ 60）

## 交接文档（节选：关键约定）

1. **GridMap 对齐规则**：position (-48,-2,-48)、cell_center (true,false,true)——违反会整体错位。
2. **get_tile 返回活引用**：改数据前 duplicate()，否则变化检测失效。
3. **湿地湿度必须饱和 1.0**：沙地下渗 0.05/tick 会吸干均分薄水，湿度卡 0.8 永不饱和。
4. **模拟游玩代替探针验收**：bug 排查用真实输入路径模拟玩家，不用断言探针；没有报错不等于没有 bug。

### 已知问题
1. AquiferRenderer3D 空网络画线报 "No vertices were added"（无害）。
2. t47 扫描墙钟热机时 350~400ms 波动（冷却后恢复）。

### 常用命令
```bash
# 运行游戏
Godot_console.exe --path D:/EmergentOasis
# 回归测试
Godot_console.exe --path D:/EmergentOasis -- t41
```

## 记忆摘要（节选）

### 用户偏好
- 决策由用户定，AI 只执行；视觉设计先给选项再动手。
- bug 排查不用探针——像真实玩家一样模拟游玩。

### 重要教训
- 倒角剖面公式写成 R-√(R²-d²) 是反的鼓包（正确：R-√(R²-(R-d)²)）。
- C# 水流"无条件写回"：flowTotal==0 时跳过写回会丢渗水量。

### 关键事实
- Godot 编辑器在 D:\godot\（绿色便携 .NET 版 4.7.2）。
- 机器连续窗口回归 2h+ 会热降频——性能类失败先冷却重跑。

## 这个示例如何体现五大循环

- **循环一**：每个阶段开工前先问正负面（"这个机制玩家会看到什么？""会不会破坏已有水流系统？"），答案写进"锁定范围/禁区"。
- **循环二**：上下文快满时按"交接文档模板"生成上面的文档，新对话读三件套即可接上。
- **循环三**：每阶段完成后对照计划书自查三层（报错/数据/体验），用户 F5 试玩后再纠偏一次。
- **循环四**：读文件只读片段、结论代替复制、记忆只存"代码读不到的信息"。
- **循环五**：用户途中说"湿地要不长草"——小想法，快速确认一句就执行并记入待办；说"新增一套生态系统"——大想法，走完整双向提问后新增阶段。

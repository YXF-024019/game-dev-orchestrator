# game-dev-orchestrator

游戏开发协作编排 Skill——用五大循环减少 AI 与用户之间的沟通损耗与 token 消耗。

- **循环一**：需求锁定（正面+负面双向提问 → 计划书锁定"要做的/不能动的" → 执行）
- **循环二**：上下文交接（主动自查，80% 时生成三件套交接文档，新对话无缝接上）
- **循环三**：自查纠偏（阶段完成+用户反馈后，报错/数据/体验三层自查 + 正反面跑偏对照）
- **循环四**：token 精简（硬规则+例外）
- **循环五**：新想法大小分流（大想法完整提问入计划书、小想法快速确认入待办）

## 安装方式

### Claude Code

方式一（推荐）：把整个 `game-dev-orchestrator` 文件夹复制到：
- 全局：`~/.claude/skills/`（所有项目可用）
- 或项目：`{项目}/.claude/skills/`（仅该项目）

方式二：把 `SKILL.md` 全文粘贴到项目的 `CLAUDE.md` 中。

### ChatGPT / 其他 AI

把 `SKILL.md` 全文复制进"自定义指令"（Custom Instructions）或系统提示中。

### 新对话开局

1. 让 AI 读 `SKILL.md`（已装则自动生效）
2. 让 AI 依次读项目目录内的三件套：`产品计划书.md` → `交接文档.md` → `记忆摘要.md`
3. 开始工作

## 文件结构

```
game-dev-orchestrator/
├── README.md               # 本文件
├── SKILL.md                # 主指令（五大循环协议）——AI 装上即用
├── templates/
│   ├── 产品计划书模板.md    # 循环一的计划书模板（含锁定范围/禁区）
│   ├── 交接文档模板.md      # 循环二的交接文档模板
│   └── 记忆摘要模板.md      # 循环二的记忆摘要模板
└── examples/
    └── 涌现绿洲示例.md      # 真实项目示例（三件套长什么样）
```

## 约定

- 全部文档存**项目目录内**，全中文，Markdown。
- 三件套必须**实时更新**（不等收尾）。
- 文档宁精勿滥：只记"下一个 AI 靠代码读不到的信息"。
